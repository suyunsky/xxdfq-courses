# xxdfq-courses Nginx部署说明

## 部署架构

```
用户浏览器
    ↓
Nginx (80端口)
    ├── 前端Vue应用 (8080端口) - 开发服务器
    └── 后端FastAPI (8000端口) - API服务
```

## 配置步骤

### 1. Nginx配置

配置文件位置：`/usr/local/etc/nginx/sites-enabled/xxdfq-simple.conf`

配置内容已包含：
- 前端代理：`/` → `http://localhost:8080`
- 后端API代理：`/api/` → `http://localhost:8000`
- CORS配置：允许跨域请求和Cookie传递
- 健康检查端点：`/health` 和 `/api/health`

### 2. 前端配置

前端已配置为使用相对路径访问API：
```javascript
// frontend/js/app.js
window.apiBaseUrl = ''; // 使用相对路径，Nginx会将/api/代理到后端
```

### 3. 后端配置

后端FastAPI服务需要运行在8000端口，并配置CORS：
```python
# backend/main.py 中已包含CORS配置
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost", "http://xxdfq.local"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

## 故障排除

### 1. CORS错误
如果出现CORS错误，检查：
- Nginx配置中的CORS头是否正确设置
- 后端CORS配置是否允许前端域名
- 前端是否使用正确的API路径（相对路径）

### 2. 502 Bad Gateway
检查：
- 后端服务是否在8000端口运行
- Nginx配置中的proxy_pass是否正确
- 后端服务日志是否有错误

### 3. 404 Not Found
检查：
- 前端路由是否正确配置（SPA需要重定向到index.html）
- 静态文件路径是否正确

### 4. Cookie不传递
检查：
- Nginx配置中的proxy_cookie_path和proxy_cookie_domain
- 前端fetch请求是否包含`credentials: 'include'`
- 后端响应头是否包含正确的Set-Cookie

## 开发环境 vs 生产环境

### 开发环境（当前配置）
- 前端：Vue开发服务器（8080端口）
- 后端：FastAPI开发服务器（8000端口）
- Nginx：代理两个服务

### 生产环境建议
1. 构建前端为静态文件：
```bash
npm run build
```

2. 修改Nginx配置，使用静态文件服务：
```nginx
location / {
    root /path/to/dist;
    index index.html;
    try_files $uri $uri/ /index.html;
}
```

3. 使用生产级后端服务器：
```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --workers 4
```

## 常见问题

### Q: 为什么需要Nginx？
A: Nginx提供：
- 统一入口点（80端口）
- 反向代理和负载均衡
- CORS处理
- 静态文件服务
- SSL/TLS终止
- 访问控制和日志记录

### Q: 可以直接访问前端或后端吗？
A: 可以，但不推荐：
- 前端：http://localhost:8080
- 后端：http://localhost:8000
但直接访问会有CORS问题，建议通过Nginx访问。

### Q: 如何添加新API路由？
A: 所有以`/api/`开头的路由都会自动代理到后端，无需修改Nginx配置。

### Q: 如何修改服务器域名？
A: 修改Nginx配置中的`server_name`：
```nginx
server_name your-domain.com www.your-domain.com;
```

### Q: 如何启用HTTPS？
A: 参考配置文件中的HTTPS配置部分，需要SSL证书。
